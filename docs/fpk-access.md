# FPK 公共部署与访问契约

本契约适用于通过 FnPackKit 接入的所有 FPK，不是独立应用、WebBridge 或“特殊打包”的专属要求。它约定应用的默认部署与访问方式，不将 fnOS 支持的其他入口格式一概视为无效。

## 宿主机运行，fnOS Web 访问

应用程序、后端、管理服务及前端资源由 fnOS 宿主机承载，可以随包安装，也可以按应用明确的部署方式独立运行或位于宿主机上的容器中。前端资源在宿主机提供，浏览器代码仍在客户端执行；业务规则和最终权限判断由后端负责。

有 Web 界面的应用默认使用下列链路，页面、API、WebSocket 和 SSE 保持在 fnOS 的同源应用前缀下：

```text
浏览器 → fnOS Web／统一网关 → 应用本机入口 → 宿主机上的业务服务
```

应用本机入口可以是原生程序自己的网关，也可以按需使用 WebBridge；不要求额外增加一层桥接。前端按当前 fnOS origin 和应用前缀生成请求地址，不能把宿主机内部的 `127.0.0.1`、Unix Socket 或独立业务端口交给浏览器直连；浏览器中的回环地址指向访问者自己的设备，不是 NAS。

默认不要求局域网 IP、独立业务域名、业务端口映射或另一个 Web 站点。业务与本机入口之间使用受保护的 Unix Socket 或显式回环地址；监听地址、容器端口发布和代理规则不得无意扩大到局域网。没有 Web 界面的服务包不必创建页面、桌面入口或 WebBridge。

## 不新增局域网登录体系，保留实际权限边界

经 fnOS Web 使用应用，不应仅因 FPK 接入而新增一套局域网账号、登录页、设备配对或浏览器持有的桥接凭据。应用复用 fnOS 身份和应用权限，并落实自身实际需要的业务权限；已有业务登录、上游账号绑定或 OAuth 不因打包而自动消失，FnPackKit 也不承诺任意应用无需适配即可免登。

下列边界与额外的局域网用户鉴权不是一回事，不能因同机运行而省略：

- fnOS 用户身份、当前应用授权及用户间的数据和控制隔离；入口可见或 NSS 账号存在本身不建立权限。
- 网关到应用的可信连接。使用共享 Go 网关时保留 `peer.Listener`、`ConnContext` 和来源策略；不直接相信浏览器提供的身份头。
- 页面、API 和长连接的应用前缀与 Origin 检查，浏览器会话按应用入口落实 CSRF 防护。
- 本机管理接口的文件权限、Unix peer 校验或适当的机器认证，防止任意本机进程执行启停、更新或读取私密连接配置。

Unix Socket 和回环 TCP 的保护方式按应用实际接口确定，不要求每种方式都额外加一套密钥。使用 WebBridge 向 TCP 后端转发 NAS 身份时，仍须配置桥接机器认证并由后端验证；机器认证由本机服务持有，不是要求用户再次进行局域网登录。具体条件见 [WebBridge 接口](web-bridge.md#端点与运行配置)。

## 局域网与中转是按需扩展

应用可以为明确用途提供局域网 API、中转、Webhook 或其他外部接入，但不能将其变成普通 FPK 使用的先决条件：

- 默认本机部署不因预留扩展而监听 `0.0.0.0`、`::` 或发布业务端口；对外开放由应用已有的可编辑运行配置和明确部署决定控制。
- 页面内的中转请求优先经同一应用前缀交给后端处理；后端向外请求不等于需要开放一个入站局域网服务。
- 确需入站局域网接口或外部回调时，按其实际来源、调用方和操作范围确定保护措施，避免绕过 fnOS 权限或本机管理边界。只开放必要路由，不将业务控制接口整体暴露。
- 缺少配置、连接失败或后端停止时明确返回真实状态，不能自动切换到局域网地址、开放监听或创建另一套登录/数据环境。

扩展继续由主应用的配置加载器和服务端策略拥有；FnPackKit 不创建平行的网络配置、身份来源或应用登记。

## 访问方式与打包内容分别选择

| 应用方式 | 程序与数据职责 |
| --- | --- |
| 原生应用随 FPK 发布 | 业务程序可以在 payload 中交付，由应用自身网关或原生入口接入；生命周期及数据路径按该应用契约处理。 |
| 独立本地应用 | 业务代码、构建产物、管理服务及生产数据在包外；FPK 提供访问桥接，可通过面板委托真实管理操作。 |
| 无 Web 界面的服务 | 由生命周期或原生服务入口运行，不因公共 Web 访问约定而增加 UI。 |

统一 Web 入口不意味着所有业务都要移到包外，也不意味着所有应用都要导入 Go、使用 WebBridge、提供控制面板或改成 root 运行。按 [公共接入入口](../AGENTS.md) 选择已有机制。

独立应用的“没有 FPK 也能运行”要求本机原生入口能操作同一业务和数据。该入口可以是本机命令、Unix Socket 或受保护的回环访问，不意味着必须开放局域网 HTTP 或建立另一套登录系统。具体进程及包生命周期边界见 [独立本地应用](independent-application.md)。

## 封包与实际运行的验证边界

应用模板、启动命令及运行配置由应用提供。FnPackKit 对 manifest、入口、网关前缀、Socket 声明和显式端口字段进行静态检查；这些检查不能证明程序的实际监听地址、代理发布范围、浏览器请求路径或权限已经正确。

显式端口入口和 CGI 声明仍按各自格式检查，格式合法不表示满足默认统一 Web 访问方式，也不表示应自动开放局域网。FnPackKit 不凭归档自动重写应用运行配置或迁移已有入口。

应用接入验证应核对实际监听、容器发布和请求链路，确认页面、API 与流经 fnOS 入口工作且不依赖业务端口直连；同时验证未授权请求不能执行管理操作。声明的网络扩展另行验证，不能用扩展入口代替默认入口验收。真实 fnOS 桌面、App、FN Connect 和具体应用的数据权限由应用维护者验证；共享夹具不能替代实机结论。
